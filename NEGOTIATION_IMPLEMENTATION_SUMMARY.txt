WHAT WAS BUILT
================================================================================

✅ CUSTOMER NEGOTIATION INITIATION
   - Customer can view quotations in Customer Portal
   - Click "Negotiate Terms" button on "Sent" status quotes
   - Opens modal form with:
     • Proposed Discount % field (1-99% validation)
     • Optional message/reasoning field
   - Submit button sends to backend
   - Auto-refresh shows updated status

✅ BACKEND NEGOTIATION PROCESSING
   - Endpoint: POST /api/portal/quotes/{id}/negotiate
   - Creates NegotiationLog entry in database
   - Validates discount percentage (1-99%)
   - Business rule: If discount > 20%, sets "Pending Approval" status
   - Otherwise: Sets "Under Negotiation" status
   - Calculates proposed total amount
   - Returns success response with status

✅ SALES REP RESPONSE CAPABILITY
   - Sales Rep views quotations dashboard
   - Click "View" button to open quote detail modal
   - Modal displays:
     • Quote summary (amount, discount, status)
     • "Negotiation History" timeline showing ALL messages
     • "Send Response to Customer" form
   - Response form fields:
     • Message (required)
     • Counter Discount % (optional)
   - Submit sends to backend
   - Response appears immediately in timeline

✅ BACKEND RESPONSE HANDLING
   - Endpoint: POST /api/portal/quotes/{id}/negotiate/respond
   - Requires sales-rep, sales-manager, or admin role
   - Creates NegotiationLog entry with sender_type="Sales"
   - Stores sender name, message, counter discount
   - Maintains quote status (doesn't change it)
   - Returns success response

✅ REAL-TIME TIMELINE VISIBILITY
   - All NegotiationLog entries returned in quote response
   - format_quote_response() builds negotiationLog array
   - Includes: sender name, message, discount, amount, timestamp
   - Customer timeline (sidebar):
     • Shows "Quote Sent" initial entry
     • Displays each negotiation message chronologically
     • Shows sender name and message content
     • Displays proposed discount if included
     • Real-time update on refresh
   - Sales Rep timeline (modal):
     • Same display as customer
     • Shows complete history for reference when responding

✅ DATA PERSISTENCE
   - NegotiationLog database table stores all messages
   - sender_type field distinguishes Customer vs Sales messages
   - sender_name field shows who sent it
   - message field contains the text
   - proposed_discount field stores discount %
   - proposed_amount field stores calculated total
   - created_at field provides audit trail timestamp
   - All messages preserved in database (audit trail)

TECHNICAL IMPLEMENTATION DETAILS
================================================================================

DATABASE:
  Table: negotiation_logs
    - id (UUID)
    - quote_id (FK)
    - sender_type (VARCHAR: "Customer" or "Sales")
    - sender_name (VARCHAR)
    - message (TEXT)
    - proposed_discount (DECIMAL)
    - proposed_amount (DECIMAL)
    - created_at (DATETIME)

BACKEND ENDPOINTS:

  1. POST /api/portal/quotes/{id}/negotiate
     Purpose: Customer proposes discount
     Auth: Customer user (get_current_user)
     Request: { proposedDiscount: 15, comment: "message" }
     Response: { success, status, proposedAmount }
     Side Effects:
       - Creates NegotiationLog (sender_type="Customer")
       - Updates quote.status (Under Negotiation or Pending Approval)
       - If discount > 20%: Creates Approval record

  2. POST /api/portal/quotes/{id}/negotiate/respond
     Purpose: Sales Rep responds to negotiation
     Auth: sales-rep, sales-manager, admin (require_roles)
     Request: { comment: "message", proposedDiscount: 12 }
     Response: { success, status, sender }
     Side Effects:
       - Creates NegotiationLog (sender_type="Sales")
       - Quote status unchanged
       - Message immediately visible in timeline

  3. GET /api/portal/quotes/{id}
     Purpose: Get quote with negotiation timeline
     Auth: Customer or Sales user
     Response includes: negotiationLog array with all messages
     Format: [{ sender, message, proposedDiscount, date }, ...]

FRONTEND COMPONENTS:

  1. CustomerNegotiation.jsx (Customer Portal)
     - Displays quotation detail with negotiation option
     - "Negotiate Terms" button (shows if status is "Sent")
     - Modal form: discount % input + message textarea
     - Validation: 1-99% discount range
     - Warning: "Discounts over 20% require managerial approval"
     - Timeline sidebar: Shows all negotiation history
     - Auto-refresh after counter-offer submitted

  2. Quotations.jsx (Sales Portal)
     - Displays quotations list with statuses
     - "View" button opens quote detail modal
     - Modal shows quote summary
     - "Negotiation History" section: Displays all timeline entries
     - "Send Response to Customer" form (appears for negotiating quotes)
     - Message textarea (required) + discount % input (optional)
     - Auto-refresh after response sent
     - List updates with new status

SERVICES:

  portalService.js:
    - submitNegotiation(id, { proposedDiscount, comment })
    - Returns: API response from POST /api/portal/quotes/{id}/negotiate

  NegotiationService (Python):
    - submit_counter_offer() - Customer proposal logic
    - verify_customer_access() - Security check
    - accept_and_confirm_quote() - Acceptance logic

BUSINESS RULES IMPLEMENTED
================================================================================

✅ Discount Validation:
   - Must be 1-99% (no zero, no 100% or more)
   - Validated on both frontend and backend

✅ Auto-Approval Threshold:
   - Discounts ≤ 20%: Quote status → "Under Negotiation"
   - Discounts > 20%: Quote status → "Pending Approval"
   - Auto-creates Approval record for manager review

✅ Customer Access Control:
   - Customers can only see their own quotations
   - Verified by company name, email, or customer ID
   - Cannot access other customers' quotes

✅ Sales Team Access Control:
   - Sales Rep can respond to negotiating quotes
   - Sales Manager can respond and approve large discounts
   - Admin can access all

✅ Message Visibility:
   - Both parties see complete timeline
   - All messages timestamped
   - Complete audit trail in database

✅ Status Management:
   - Quote status updates when negotiation starts
   - Status maintained during back-and-forth
   - Only customer can confirm to move to "Confirmed"

HOW TO USE
================================================================================

AS A CUSTOMER:
  1. Login to Customer Portal (email: customer@dealflow360.com)
  2. View quotation with status "Sent"
  3. Click "Negotiate Terms" button
  4. Enter discount % (e.g., 15) and message
  5. Click "Submit Counter Offer"
  6. See success message and updated timeline

AS SALES REP:
  1. Login to Sales Portal (email: salesman@dealflow360.com)
  2. Go to Quotations page
  3. Find quote with "Under Negotiation" status
  4. Click "View" button
  5. See customer's proposal in "Negotiation History"
  6. Scroll down to "Send Response to Customer"
  7. Enter message and optional counter discount
  8. Click "Send Response"
  9. See success message and updated timeline

AS CUSTOMER (SEEING RESPONSE):
  1. Go back to Customer Portal
  2. View same quotation
  3. See complete timeline including sales rep's response
  4. Can continue negotiating or accept quote
